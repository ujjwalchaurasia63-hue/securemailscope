## 1. Executive Summary

SecureMailScope is an evidence-first, offline network capture analysis engine for passive cryptographic security posture assessment of email protocols (SMTP, IMAP, and POP3).

It inspects raw `.pcap` and `.pcapng` network packet traces, reconstructs TCP conversations across email protocols, tracks opportunistic STARTTLS state transitions, extracts TLS cryptographic parameters, evaluates deterministic compliance rules (RFC / NIST), and isolates statistical outliers using unsupervised machine learning.

Every finding generated by SecureMailScope is backed by exact forensic evidence: packet frame numbers, relative timestamps, byte offsets, and governing RFC citations.

## 3. Quickstart & Verification

### Runtime Environment
- **Reference Baseline**: Python 3.11 (per Handbook specification).
- **Verified Runtime**: Python 3.14.7 on Windows 11 with TShark 4.4.5 / 4.6.8.
- **System Dependency**: TShark / Wireshark (available in PATH or `C:\Program Files\Wireshark\tshark.exe`).

### 1. Verify Environment Diagnostics
```bash
python main.py --check-env
```

### 2. Run Automated Test Suite (33 Tests)
```bash
python -m pytest tests -v
```

### 3. Run Standalone CLI Ingestion
```bash
# Analyze demo PCAP and view terminal security report
python main.py data/demo_mail_traffic.pcap

# Export machine-readable structured JSON
python main.py data/demo_mail_traffic.pcap --json results/demo_result.json
```

### 4. Launch Interactive Streamlit Visualization
```bash
# Direct Streamlit launch (recommended)
python -m streamlit run main.py

# Or via CLI flag
python main.py --ui

# One-Click Launchers:
# Windows:
.\run_demo.bat
# Linux / macOS:
./run_demo.sh
```
Open `http://localhost:8501` to view the interactive dashboard.

### 5. Docker Container Deployment (Zero-Setup)
```bash
# Using Docker Compose (Recommended)
docker compose up -d

# View logs
docker compose logs -f
```
Open `http://localhost:8501` in your browser. All dependencies including TShark are bundled.

## 4. Key Architectural Features

### Layer 1: Deterministic Compliance Engine
- Enforces **seven mandatory baseline rules** plus **three supporting certificate checks**:
  - `RULE_TLS_LEGACY` (HIGH) — NIST SP 800-52 Rev. 2 §3.1, RFC 8996
  - `RULE_CIPHER_BROKEN` (HIGH) — RFC 7465, RFC 7590, NIST SP 800-52 Rev. 2 §3.3
  - `RULE_PLAINTEXT_AUTH_BEFORE_TLS` (CRITICAL) — RFC 2595 §3.2, RFC 8314 §3, NIST SP 800-45
  - `RULE_STARTTLS_NOT_ENFORCED` (MEDIUM) — RFC 3207 §4.1, RFC 8314 §5.1
  - `RULE_CERT_EXPIRED` (CRITICAL) — RFC 5280 §4.1.2.5, NIST SP 800-52 Rev. 2 §3.2
  - `RULE_HOSTNAME_MISMATCH` (CRITICAL) — RFC 6125
  - `RULE_TLS_HANDSHAKE_FAILURE` (HIGH / MEDIUM) — RFC 8446 §6
  - *Supporting*: `RULE_CERT_SELF_SIGNED` (HIGH), `RULE_CIPHER_NON_AEAD` (LOW), `RULE_CERT_EXPIRING_SOON` (LOW)
- Aggregates severity using maximum severity hierarchy:
  $$\text{Session Severity} = \max(\text{fired rule severities})$$
  $$\text{CRITICAL} > \text{HIGH} > \text{MEDIUM} > \text{LOW} > \text{CLEAN}$$

### Layer 2: Unsupervised Anomaly Intelligence
- Evaluates a standardized 9-dimensional session vector using `sklearn.ensemble.IsolationForest`.
- Features: `handshake_duration_ms`, `offered_cipher_count`, `cipher_rarity_score`, `payload_bytes_avg`, `payload_bytes_var`, `packet_count`, `tls_version_encoded`, `cipher_suite_encoded`, `ja3_hash_encoded`.
- Strictly an **Anomaly Score / Behavioral Outlier Indicator** ($[0.0, 1.0]$, threshold $0.70$).
- Fully decoupled from deterministic compliance severity.

### Layer 3: Hardening & Remediation Recommendations
- Downstream advisory guidance: Generates actionable Postfix and Dovecot configuration snippets.
- Marked as **Administrator Action** (Advisory Only). SecureMailScope never alters server configurations automatically.

## 5. Synthetic Demonstration Scenarios

The bundled `data/demo_mail_traffic.pcap` contains 9 verified test scenarios (101 packets) generated using Scapy and RFC 5737 documentation subnets:

| Stream | Protocol | Scenario Description | Severity | Fired Rules |
|---|---|---|---|---|
| 0 | SMTP (587) | Modern TLS 1.3 / AES-GCM Baseline | **CLEAN** | *(None)* |
| 1 | SMTPS (465) | TLS 1.0 + Broken 3DES Cipher | **HIGH** | `RULE_TLS_LEGACY`, `RULE_CIPHER_BROKEN`, `RULE_CIPHER_NON_AEAD` |
| 2 | SMTP (25) | Plaintext Auth Transmitted Before TLS | **CRITICAL** | `RULE_PLAINTEXT_AUTH_BEFORE_TLS` |
| 3 | IMAP (143) | STARTTLS Advertised but Ignored | **MEDIUM** | `RULE_STARTTLS_NOT_ENFORCED` |
| 4 | IMAPS (993) | Expired Certificate (TLS 1.2) | **CRITICAL** | `RULE_CERT_EXPIRED`, `RULE_CIPHER_NON_AEAD` |
| 5 | POP3S (995) | Self-Signed X.509 Certificate | **HIGH** | `RULE_CERT_SELF_SIGNED`, `RULE_CIPHER_NON_AEAD` |
| 6 | SMTP (587) | Handshake Failure (Fatal Alert) + 580ms Delay | **HIGH** | `RULE_TLS_HANDSHAKE_FAILURE` *(Anomaly Score: 0.958)* |
| 7 | IMAPS (993) | Subject Alternative Name Mismatch | **CRITICAL** | `RULE_HOSTNAME_MISMATCH`, `RULE_CIPHER_NON_AEAD` |
| 8 | POP3 (110) | Unencrypted Cleartext Authentication | **CRITICAL** | `RULE_PLAINTEXT_AUTH_BEFORE_TLS` |
